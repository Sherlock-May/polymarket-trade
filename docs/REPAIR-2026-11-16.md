# 迁移环境与旧订单对账修复

2026-11-16，北京时间约 22:00 完成只读账户核实与本地恢复。

## 根因与证据

- 迁移来的虚拟环境指向旧机器 `C:\Users\sui\...` 的 Python，当前机器无法执行。已用本机 Python 3.11.9 重建 `.venv`，依照 `requirements.lock` 安装，`pip check` 通过。原环境保留在 `.venv-migrated-backup`。
- 4 笔旧 SOL 5 分钟买单的详情响应均为 JSON `null`，触发 SDK 的 `UnexpectedResponseError`，底层验证错误为根对象 `model_type`。
- 分别按订单 ID 查询也均为空；两个相关市场的挂单与成交查询均为空；4 个资产的账户份额余额均为零。用户确认迁移前后私钥与钱包相同。
- 原实现对账遇错中断并禁止新开仓；失败没有更新重试时间，撤单请求又重复打印，导致持续刷屏。

## 修复

- 详情为 null 时，尝试按精确订单 ID 交叉查询。官方说明该过滤器也能查询已撤销或完全撮合的订单，参见 [订单管理文档](https://docs.polymarket.com/trading/manage-orders)。其他格式异常继续报错，避免掩盖接口变化。
- 仅对已知 GTD 入场买单，在轮次结束和到期后额外等待 60 秒、无挂单、无相关成交、无本地成交记录且账户该资产份额为零时，恢复为 `EXPIRED`。记录 `status_source=gtd_expiry_cross_checked` 与核实时间，不伪造交易所撤单确认。
- 未知提交、有成交、持仓非零、卖单或证据不足的情况继续保留待核实，不释放风险限制。
- 失败对账遵守配置间隔；撤单采用递增重试间隔，上限 60 秒。日志增加代码位置和字段验证类型，不输出响应值或异常原文。
- 新增 `main.py reconcile`：单实例锁、数据库备份、只读账户查询、本地状态更新与报告导出，不提交买卖、撤单或赎回。
- 离线报告正确显示 `running=false`。测试市场开关不再依赖用户当前启用的配置。
